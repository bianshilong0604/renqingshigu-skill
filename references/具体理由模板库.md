# 具体理由模板库

> 用途：为拒绝、改期、无法赴约等低风险社交场景提供具体、日常、可应对一次追问的理由候选。  
> 说明：这里是话术候选，不是用户事实；使用时选择与现实相符、或用户愿意采用的版本，再按自己的语气改写。

## 1. 使用规则

一个能防追问的理由应包含三部分：

1. 具体事件：是什么安排，而不是“有点事”“个人事务”。
2. 合理约束：为什么今晚不能挪，例如提前约好、多人时间难凑、需要本人到场。
3. 结论复位：回到“今晚不能替班”，不继续解释到可以被逐条协商。

推荐结构：

```text
具体安排 + 已提前约定/时间难凑/需要本人到场 + 今晚不能调整
```

这些模板适用于话术演练或用户明确要候选版本的情况。若用户要发送真实消息，应让用户从候选中选择符合自身情况的版本；不能把 Skill 自动生成的候选当成已经发生的事实。

## 2. 低风险具体理由候选

### 2.1 老同学或朋友聚会

**追问**：“什么约？”

**回答**：

> 今晚和高中同学约了聚餐，大家时间一直很难凑到一起，我不太方便临时取消。

适用逻辑：提前约定、多人协调成本高、取消会影响关系；不需要补充餐厅、人数和具体时间等细节。

### 2.2 父母或家人来吃饭

**回答**：

> 今晚我父母过来一起吃饭，之前就约好了，我得陪他们，确实没法改。

适用逻辑：家庭安排、本人需要在场、时间已提前锁定；不需要解释家人为什么来或具体吃什么。

### 2.3 已预约的个人事项

**回答**：

> 今晚有一个提前约好的预约，时间已经定了，临时改不了，所以确实没法替班。

适用逻辑：用户确实有预约但不想公开具体内容；如果对方继续追问，可重复“是提前约好的个人预约，具体就不展开了”。

### 2.4 已答应参加的固定活动

**回答**：

> 我今晚已经答应参加一个提前安排好的活动，时间上确实冲突，临时取消不太合适。

适用逻辑：活动已经确认、取消会影响他人；不要再虚构活动名称或主办方。

### 2.5 需要处理的家庭事务

**回答**：

> 我今晚有件提前安排好的家里的事需要处理，时间上挪不开，所以不能替班。

适用逻辑：用户确有家庭事务但不愿展开；若对方追问，直接回到“家里的安排，具体不太方便细说，今晚确实不行”。

## 3. 防追问的递进方式

| 对方反应 | 推荐回答 | 目的 |
|---|---|---|
| “什么约？” | 给一个具体事件 + 一个合理约束 | 消除“随口找借口”的感觉 |
| “不能改到别的时间吗？” | 说明已提前约定/涉及他人，再重复今晚不能 | 解释不可调整性，不开启谈判 |
| “就替几个小时也不行？” | “今晚确实不行，这次没法替；你再问问其他同事看看。” | 回到边界，停止新增细节 |
| 继续盘问细节 | “具体安排我就不展开了，但今晚确实不能替班。” | 保留隐私，结束追问 |

## 4. 不使用的理由

除非用户明确提供并授权使用，不主动生成以下理由：

- 疾病、就医、事故、亲属重病或死亡。
- 孩子生病、照护危机或其他可能引发对方强烈关心的事件。
- 重大财务困难、法律问题或会让对方继续追问的高风险故事。
- 容易被核验、需要继续维护的复杂谎言。

理由的目标是让边界自然、具体和稳定，不是制造一套更大的解释负担。
